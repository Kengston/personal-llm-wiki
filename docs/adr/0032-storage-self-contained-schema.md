# ADR-0032 — Хранилище самодостаточно: схема живёт в `CLAUDE.md` контент-репо, движок её потребитель

> Уточняет [ADR-0003](0003-two-repos-public-private.md) (два репо) и [ADR-0010](0010-wiki-content-model.md) (контент-модель). Не отменяет ни одного из них: граница «код ≠ данные» остаётся, меняется владелец схемы.

**Контекст.** Контракт хранителя вики (`compiler/rules.md`, 562 строки) живёт в публичном движке, а `CLAUDE.md` приватного хранилища только ссылается на него и добавляет «специфику». За лето хранилище получило то, чего контракт не знает: JSONL-леджеры воронки ([ADR-0028](0028-career-data-module.md)–[ADR-0031](0031-hh-channel.md)), базу знаний `knowledge/` ([ADR-0019](0019-knowledge-library-external-methodology.md)), рабочие заметки, документы резюме. `AGENTS.md` хранилища отстал на 14 ADR. Основной сценарий владельца сегодня: работа со хранилищем напрямую через Claude Code и скиллы (поиск работы, скоро обучение), а не через Telegram-мост. Схема в чужом репозитории при таком сценарии читается реже, чем нарушается.

**Решение.**

### 1. `CLAUDE.md` хранилища = схема по Карпатому, единственная и полная

Файл описывает сам, без ссылок на движок как на источник правил: полки и что в них лежит, типы страниц с frontmatter, три операции (ingest, query, lint) шагами, правила ссылок и разрешения противоречий, формат `log.md`, форматы леджеров и где их zod-схемы, реестр площадок, учебный контур. Глоссарий терминов в `CONTEXT.md` рядом. `AGENTS.md` сводится к указателю «читай `CLAUDE.md`».

### 2. `compiler/rules.md` движка становится generic-шаблоном

Он описывает поведение по умолчанию для любой инсталляции фреймворка и синтетический `wiki-example/`. Конкретная инсталляция может расширять набор типов страниц и полок в своём `CLAUDE.md`; движок не проверяет соответствие `rules.md` при работе с чужим корнем. Первые расширения этой инсталляции: типы `platform`, `source`, `transcript`; полки `work/`, `learning/`, `docs/`, `wiki/jobsearch/`.

### 3. Движок читает только фиксированные пути

Пути, которые движок открывает кодом, перечислены в схеме как «не переименовывать без правки движка»: `raw/jobsearch/*.jsonl`, `raw/career/`, `raw/learning/reviews.jsonl`, `wiki/projects/`, `wiki/growth/*.md` (скан `target_date`), `wiki/index.md`, `reminders/`, `knowledge/<topic>/`. Всё остальное дерево принадлежит схеме хранилища и может меняться без релиза движка.

### 4. Полки, которых в контент-модели не было

- `work/` — живые мутируемые заметки и списки (не знание). Возвращает `raw/` иммутабельность: рабочие файлы из `raw/jobsearch/*.md` переезжают сюда.
- `docs/` — документы человека (резюме, портфолио, архив спецификаций). Узаконен как полка, не индексируется вики.
- `learning/` — учебный воркспейс ([ADR-0034](0034-learning-contour.md)).
- `wiki/jobsearch/` — параметры прогона, реестр площадок, сводка воронки, журнал решений подсистемы ([ADR-0033](0033-platform-registry-and-vacancy-identity.md)).

**Рассмотрено и отвергнуто.** Оставить контракт в движке и «доложить» полки в `CLAUDE.md`: воспроизводит текущее отставание, потому что правки правил идут в один репо, а нарушения обнаруживаются в другом. Полностью отвязать хранилище от движка: теряет валидацию леджеров zod и CLI, которые и удерживают данные от порчи.

**Следствия.** Публичный `lint:public` продолжает гарантировать ноль личных данных в движке; схема с личными путями теперь в приватном репо, где ей и место. Финансовый модуль движка, не имеющий данных в хранилище, закрывается флагом `FINANCE_ENABLED` (по умолчанию выключен) как часть этого же шага.
