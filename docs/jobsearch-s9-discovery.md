# S9 — discovery: подключить сеть к реестру компаний

Слайс закрывает третий канал добычи компаний (`web_search`) — единственный
непроработанный пункт [ADR-0029](adr/0029-company-discovery-and-network-access.md).
Слайсы S1–S8 сделаны и смержены; здесь только то, чего не хватает.

## 1. Зачем

Загрузчик с allowlist, robots и rate-limit написан и покрыт офлайн-тестами. Детерминированный
парсер страницы — тоже. **Их никто не вызывает:** routine, которую ADR-0029 §7 описывает как
один пакетный прогон в сутки, не существует. Из-за этого не работает и всё, что за ней стоит:
сырьё нигде не сохраняется, `source_class` в классификатор не добавлены, записи `opportunity`
не заводятся, а поле `application.opportunity_id` заполнить нечем.

Практическое следствие: компании и вакансии заводятся только руками и импортом файла. Для
точечного поиска этого хватает, но «покажи, что нового у моих компаний» система ответить
не может.

## 2. Сначала снять двусмысленность в названии канала

**`web_search` в этой системе НЕ означает «поиск в поисковике».** Движок лишён сети, а
поисковая выдача — не домен из allowlist и не источник, который можно уважать по robots.
Под каналом понимается ровно две вещи:

1. **обход карьерных страниц уже заведённых компаний** — `company.site_domain` плюс типовые
   пути (`/careers`, `/jobs`, `/vacancies`), детерминированно, без всякого «поиска»;
2. **обход явно заданных владельцем подборок** — список URL в приватном конфиге.

Если из этого захочется сделать настоящий поисковый запрос — это отдельное решение и отдельный
ADR, а не расширение слайса. Зафиксировать формулировку в ТЗ нужно до кода: иначе «канал
веб-поиска» через месяц прочитают буквально.

## 3. Что уже есть — не переписывать

| Готово | Где |

| Загрузчик: allowlist с перепроверкой редиректов, robots (fail-closed при недоступности), rate-limit, потолок размера с потоковым обрывом, один ретрай, «никогда не бросает» | `src/bridge/net/fetcher.ts` |

## 4. Объём работ

### 4.1. Конфиг allowlist

- Переменная окружения со списком доменов; в `.env.example` — **только** `example.com`,
  рабочий список приватно ([ADR-0003]).
- Пустой список = deny-by-default: прогон не делает ни одного запроса и говорит об этом.
- Записи с ведущей точкой разрешают поддомены (поведение `hostAllowed` уже такое).

**DoD:** `pnpm lint:public` зелёный; тест на то, что при пустом allowlist сеть не трогается.

### 4.2. Источник URL для обхода

- Из реестра: для каждой компании с `hiring_status != 'paused'` — её домен плюс типовые пути.
- Из конфига: список URL подборок (приватно, рядом с allowlist).
- Порядок обхода детерминированный (сортировка по домену), чтобы прогон был воспроизводим.

**DoD:** чистая функция «реестр + конфиг → список URL», покрытая тестом; никакой сети внутри.

### 4.3. Routine `jobsearch-discovery`

Рядом с digest-sweep ([ADR-0007]), **один пакетный прогон в сутки**.

- Не более 3 хостов за прогон; лимит запросов на хост уже в загрузчике.
- Обход **последовательный**, никаких параллельных вееров.
- На входящее сообщение НЕ запускается никогда.
- Прогон не падает целиком из-за одного хоста: загрузчик возвращает `null`, discovery
  деградирует и говорит, сколько источников оказалось доступно.

**DoD:** routine вызывается из реального расписания, и на подключение стоит тест по исходнику —
как у `runJobsearchSweep`. «Написано и не подключено» — это не работающая фича, и в этом
слайсе такая ошибка была бы повторной.

### 4.4. Сохранение сырья

- Файл `raw/jobsearch/<host>/<sha256-тела>.md` через `failClosedSanitize`.
- Frontmatter: `source_class: web:untrusted`, `status: immutable`, `date`, `source_url`
  **без query**.
- Content-address по хешу ТЕЛА, а не по времени: повторный обход неизменившейся страницы не
  плодит файлы. `existsSync`-гард как backstop — иммутабельное не перезаписывается.

**DoD:** тест на повторный обход (второй раз файл не создаётся); тест на то, что путь проходит
`shouldSkipRawPath` у обходчиков `raw/`.

### 4.5. `source_class` в классификаторе

Добавить `web:untrusted` и `linkedin:export` ([ADR-0029], «Следствия»).

**DoD:** документ с пятью и более PII уходит в карантин целиком, а не «подчищается».

### 4.6. Запись `opportunity`

Из полей парсера: `company_id` (дедуп по домену; компании нет — завести с
`company_source: 'web_search'`), `title`, `source_url` без query, `posted_at` (nullable —
отсутствие даты информативно), `fetched_at`, `employment_type`, `remote_mode`, `raw_ref` на
сохранённое сырьё.

Провенанс заполняется целиком: `content_sha256`, `parser_version`, `robots_ok` — из
`FetchedDoc`, а не константами.

**DoD:** запись без провенанса не создаётся; `application.opportunity_id` становится
заполнимым; тест на дедуп повторной вакансии.

### 4.7. Отчёт о прогоне

Детерминированный текст: сколько хостов обошли, сколько вакансий новых, что отсеяно гейтами
и почему, плюс `sourceCoverageLine`. **Хода движка в прогоне не делать** — ADR допускает один,
но сводка здесь чисто арифметическая, а лишний ход это лишние деньги и лишний недетерминизм.
Если сказать нечего — молчать.

**DoD:** тест, что при нулевом улове пуш не отправляется.

## 5. Чего в слайсе НЕ делать

- **Не снимать `deny: [WebFetch, WebSearch]`** с движка — это lethal trifecta ([ADR-0007]).
- **Не скрейпить LinkedIn** ни авторизованно, ни через cookie: риск бана канала, который по
  методологии и есть основной.
- **Не заводить headless-браузер.** Страница не отдаёт HTML — канал возвращает `null`.
- **Не подавать сырой текст страницы в промпт.** Извлечение делает код; LLM-извлечение —
  отдельный ADR-аддендум с изоляцией хода ([ADR-0029] §6.6).
- **Не автоматизировать отклики и коннекты.** Система готовит и ранжирует, отправляет человек.

## 6. Ловушки

- **Загрузчик обязан оставаться «никогда не бросает».** Соблазн пробросить ошибку наверх, чтобы
  «увидеть проблему», ломает контракт: один недоступный хост не должен ронять прогон.
- **`fetchFn` инъектируется, живой сети в тестах нет.** Тест с реальным HTTP в этом проекте
  молча вешает прогон.
- **Санитайзер портит соседние данные.** Через `failClosedSanitize` идёт только сырьё и
  свободный текст; `source_url`, `external_id` и прочие типизированные поля — мимо.
- **Числовые идентификаторы в свободном тексте пишутся с буквенным префиксом без разделителя**
  (`li4021234567`), иначе маскер превратит их в `[REDACTED:phone]`.
- **Бюджет прогона — свойство экземпляра загрузчика.** Один `BridgeFetcher` на прогон, иначе
  счётчики «20 запросов на хост» обнуляются на каждом вызове.

## 7. Порядок

1. Конфиг allowlist и источник URL (чистые функции, тесты офлайн).
2. Сохранение сырья + `source_class` — до записи `opportunity`, потому что `raw_ref` ссылается
   на файл.
3. Запись `opportunity` и провенанс.
4. Routine и подключение к расписанию + тест на подключение.
5. Отчёт о прогоне.
6. Обновить `docs/jobsearch-guide.md`: перенести канал `web_search` из раздела «написано и не
   подключено» в «работает», и снять оговорку про автопоиск.
